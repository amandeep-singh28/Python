->VPC Fundamentals
It stands for virtual(It is not physical) private cloud.
Inside AWS we create our own network.
Along with the infrastructure, AWS provides us private cloud which helps us to deploy our EC2 instances.

If server would be in same place, than there will be no security, anyone could access them, No privacy.
Using VPC each customer gets their own network inside AWS, their own IP address(range) and their own security.

->CIDR + IP Addressing 
Whenever u r creating your VPC, u need to decide your ID address range
10.0.0.0/16 -> This is called CIDR notation

10.0.0.0 -> Starting address
16 -> Size of network
Lesser the number(after /) -> Larger network
More the number(after /) -> Smaller network

->Subnet
Smaller network inside VPC
Inside AWS you created VPC and inside VPC there is Subnet.
There is a big organization so you have stored the data on VPC and in organization there are various department so those departments represents Subnet.


Subnet: 10.0.1.0/24

- Total IPs = 256
- AWS reserves 5 IP addresses
- Usable IPs = 251

Reserved IPs:
- First IP (network address)
- Second IP (VPC router)
- Third IP (DNS)
- Fourth IP (reserved by AWS)
- Last IP (broadcast)

->How to create your VPC
Search VPC
Create VPC
Give it a name(VPC-Test-1)
IPV4 CIDR(10.0.0.0/16) -> 65K around IP address
Rest on default.

Then Create a subnet for VPC-Test-1
Give this (10.0.0.0/24)

/16 creates around 65,536 IP addresses in the VPC.

When we create a subnet with /24, it means that a block of 256 IP addresses 
(from that /16 range) is allocated to that subnet.
