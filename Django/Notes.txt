Django Admin & Superuser – Short Notes

1. migrate:
Command: python manage.py migrate
- Creates database tables.
- Required for authentication and admin system.

2. createsuperuser:
Command: python manage.py createsuperuser
- Creates an admin account with full permissions.
- Allows access to the admin panel.

3. runserver:
Command: python manage.py runserver
- Starts the development server.

4. Admin Panel:
URL: http://127.0.0.1:8000/admin/
- Login using superuser credentials.
- Manage users and models (Add, Edit, Delete).

Django Admin is a built-in powerful tool that provides automatic CRUD operations and user management without writing extra frontend code.

->Users and groups

Django Users and Groups – Short Notes

1. Users:
- Represents individual accounts.
- Stores username, password (hashed), email, etc.
- Types:
  • Normal User – No admin access.
  • Staff User – Can access admin panel (limited permissions).
  • Superuser – Has all permissions.

2. Groups:
- Collection of users.
- Used to assign permissions to multiple users at once.
- Helps implement Role-Based Access Control (RBAC).

Example:
Instead of giving permissions to each user individually,
create a group (e.g., Editor, Manager) and assign permissions
to the group, then add users to that group.

Django uses:
- User model
- Group model
- Permission model

->>>API (Application Programming Interface)
-API is a communication bridge between two software systems.
-It works as middleware between the frontend and backend, or between two different applications.
-It allows applications to exchange data securely without giving direct access to internal systems.
-Most modern APIs send data in JSON (JavaScript Object Notation) format.

->>>>Django and Flask
-Django and Flask are backend frameworks.
-They are generally considered monolithic frameworks because:
-Frontend and backend can exist in the same project.
-They handle routing, business logic, database, and templates together.
-However, they can also be used to build APIs that serve data to:
    React frontend
    Mobile applications
    Other third-party systems

Example 1: Uber and Google Maps
When a user books a ride in Uber:
Uber needs location and navigation services.
Instead of building its own map system, Uber uses Google Maps API.
Google provides:
    Location data
    Directions
    Distance calculation
Uber receives only restricted access to these services through the API.
It does not access Google's internal system directly.

API ensures:
-Security
-Controlled access
-Structured communication

Example 2: Domino’s and Zomato
You can order Domino’s from Zomato even though they are separate companies.
How it works:
    Domino’s provides its menu and order system through an API.
    Zomato connects to that API.
    Zomato fetches menu data in JSON format.
    When you place an order, Zomato sends the request back to Domino’s system using the API.
    Zomato does not access Domino’s database directly.
    It only accesses permitted data through the API.

****Serializer.py****
In Django REST Framework, a Serializer is responsible for:
    Converting Python/Django model objects → JSON
    Converting JSON → Python objects
This process is called:
Serialization → Object to JSON
Deserialization → JSON to Object

->Why do we need it??
Client (frontend or Postman) communicates in JSON format.
But Django works with:
    Python objects
    Model instances
So Serializer acts like a translator between:
Backend (Python objects) ↔ Client (JSON data)

(iv)In views.py
    class ProductViewSet(viewsets.ModelViewSet):
    serializer_class = ProductSerializer
    filter_backends = [DjangoFilterBackend]
    filterset_fields = ['name', 'price'] 

    def get_queryset(self):
        queryset = Product.objects.all()
        min_price = self.request.query_params.get('min_price')
        max_price = self.request.query_params.get('max_price')

        if min_price:
            queryset = queryset.filter(price__gte = min_price)
        if max_price:
            queryset = queryset.filter(price__lte = max_price)
        
        return queryset

It creates tokens but that token is not stored in database. You don't have to store every user data, you just create tokens.
Pass to the server and server verifies it.
