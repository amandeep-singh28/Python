****Function Based Views****
A simple python function that handles request and returns response.
Advantages:-Easy to understand, Good for small logic
Disadvantages:-Code becomes messy in large projects

->Class Based Views
Same thing, but using classes

from Django.views import View
class HelloView(View):
    def get(self, request):
        return HttpResponse("Hello World from Class-Based-View")

-URL for CBV
from app.views import HelloView
path('hello-cbv/', HelloView.as_view())

What is as_view()?
It converts class into a callable view function

FBV is used in small projects but CBV is used in large projects

Example for FBV:-

from django.http import JsonResponse
import json

students = [
    {"id": 1, "name": "Aman"},
    {"id": 2, "name": "Rahul"}
]

def student_view(request):

    if request.method == "GET":
        return JsonResponse(students, safe=False)

    elif request.method == "POST":
        body = json.loads(request.body)
        students.append(body)
        return JsonResponse({"message": "Student added"})

Example for CBV:-

from django.views import View
from django.http import JsonResponse
import json

students = [
    {"id": 1, "name": "Aman"},
    {"id": 2, "name": "Rahul"}
]

class StudentView(View):

    def get(self, request):
        return JsonResponse(students, safe=False)

    def post(self, request):
        body = json.loads(request.body)
        students.append(body)
        return JsonResponse({"message": "Student added"})


Conclusion:-
“In FBV, handling multiple HTTP methods leads to large conditional blocks, making the code hard to maintain. CBVs solve this by mapping HTTP methods to class methods like get() and post(), resulting in cleaner and scalable code.”


****DRF Basics — APIView vs GenericAPIView vs ViewSet****
->What is DRF??
Django rest framework is used to build APIs. Instead of returning a HTTP response, we return a JSON file.

->Normal View VS API View
In Django, Normal View returns a HTML pages which are directly shown in the browser. But API view is used when we only want to send the data, not a full webpage. This data can be used by mobile apps or frontend frameworks like React to build the UI.
Django Normal View - Data + UI
Django API View - Only Data

->Generic View
GenericAPIView extends APIView and provides built-in functionality like queryset and serializer handling, making it easier to implement common CRUD operations with less code. It adds QuerySet and Serializer. Reduces Manual Work

->ViewSet(Most Powerful)
It handles all CRUD operations automatically

->Why we send Response instead of HttpResponse in DRF??
Because HttpResponse sends raw data, no automatic JSON handling. But Response automatically converts to JSON and it is also API friendly.
We can also create APIs through HttpResponse but we have to manually do everything like converting data to JSON.


****Serializers****
It converts python object to JSON and vice versa.
It does three important things:- (i)Validation (ii)Conversion and (iii)Save to database

What is the need of this??
It validates and structures the data.
Django models are like this:- Student(name="Amandeep", age=21)
But API need JSON structured data
Serializer does this for you.

But Response also doing the conversion to JSON only, then why there is need for Serializers?
Because Serializers also validates our data for each field. If in integer field we have typed a string, than it writes like "age must be of integer". And also it saves our data to the database


->Types of Validation in Serializer
(i)Field Level Validation
Used when you want to validate a single field. It validates only ONE field at a time
Syntax:- def validate_<fieldname>(self, value):
Example:-
class StudentSerializer(serializers.Serializer):
    name = serializers.CharField()
    age = serializers.IntegerField()

    def validate_age(self, value):
        if value < 18:
            raise serializers.ValidationError("Age must be 18+")
        return value

(ii)Object Level Validation
Used when validation depends on multiple fields
Syntax:- def validate(self, data):
Example:-
class StudentSerializer(serializers.Serializer):
    name = serializers.CharField()
    password = serializers.CharField()
    confirm_password = serializers.CharField()

    def validate(self, data):
        if data['password'] != data['confirm_password']:
            raise serializers.ValidationError("Passwords must match")
        return data

->Important Point
“We must call is_valid() before save() because it validates and prepares the data. Without it, validated_data is not available and DRF prevents saving invalid data.”

****Relationship****
Three types of relationships are there:-
(i)Foreign Key (One to Many)
One teacher -> Many students

class Teacher(models.Model):
    name = models.CharField(max_length = 100)
class Student(models.Model):
    name = models.CharField(max_length = 100)
    teacher = models.ForeignKey(Teacher, on_delete = models.CASCADE)

(ii)Many to Many
One student -> Many Course
One Course -> Many students

class Course(models.Model):
    name = models.CharField(max_length=100)

class Student(models.Model):
    name = models.CharField(max_length=100)
    courses = models.ManyToManyField(Course)

(iii)One to One
One user -> One Profile

class Profile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)


What does on_delete=models.CASCADE do?
“If the parent object (Teacher) is deleted, all related child objects (Students) will also be deleted.”


->Showing Relationship in Serializers(IMP CONCEPT)
Right now, what we did?
We have just create two models(Teacher and Student) and the relationship was One To Many(One Teacher can taught many Students).
So, in our Student model, another column will be made which will be "teacher_id"(Since it is connected).
So, only ID is stored, not full teacher data.
If, we call API we will get teacher_id = 1, but where are the details of that teacher, Who is teacher = 1??
Than you will need another API call to get this.

This problem is solved by nested Serializer...

class TeacherSerializer(serializers.ModelSerializer):
    class Meta:
        model = Teacher
        fields = '__all__'


class StudentSerializer(serializers.ModelSerializer):
    teacher = TeacherSerializer()   # 🔥 important

    class Meta:
        model = Student
        fields = '__all__'

Now our output becomes:-
{
  "id": 1,
  "name": "Amandeep",
  "age": 21,
  "teacher": {
    "id": 1,
    "name": "Richa"
  }
}

->Important Point(Use Nested Serializer for get only, add the data through admin panel)
"Nested serializers are primarily used for read operations. For write operations, we need to override create and update methods, which is why in practice we usually use IDs for POST and nested serializers for GET.”


****Status Code****
When your API responds, it sends two things:-
(i)Data (JSON)
(ii)Status code

Example:-
{
    "name" : "amandeep"
}
Along with this, server also sends:
201 created

Code    Meaning     When to use 
200	    OK	        GET success
201	    Created	    POST success
400	    Bad Request	Validation error
404	    Not Found	Object not found

->Implementation
Add this in your views.py
class StudentAPIView(APIView):

    def get(self, request):
        students = Student.objects.all()
        serializer = StudentSerializer(students, many=True)
        return Response(serializer.data)

    def post(self, request):
        serializer = StudentSerializer(data=request.data)

        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status = status.HTTP_201_CREATED)

        return Response(serializer.errors, status = status.HTTP_400_BAD_REQUEST)

When you will post the data, you will see HTTP_201_CREATED
And when some validation gets failed, you will see HTTP_400_BAD_REQUEST. To perform this add this in serializer.py
def validate_age(self, value):
        if value < 18:
            raise serializers.ValidationError("Age must be 18+")
        return value

->Difference between status code 200 and 201??
“200 OK is returned for successful GET requests, while 201 Created is returned when a new resource is successfully created via POST.”

****Authentication VS Authorization****
Authentication means "Who are you?", login, token and session
Authorization means "What are you allowed to do?"
