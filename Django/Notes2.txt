****Function Based Views****
A simple python function that handles request and returns response.
Advantages:-Easy to understand, Good for small logic
Disadvantages:-Code becomes messy in large projects

->Class Based Views
Same thing, but using classes

from Django.views import View
class HelloView(View):
    def get(self, request):
        return HttpResponse("Hello World from Class-Based-View")

-URL for CBV
from app.views import HelloView
path('hello-cbv/', HelloView.as_view())

What is as_view()?
It converts class into a callable view function

FBV is used in small projects but CBV is used in large projects

Example for FBV:-

from django.http import JsonResponse
import json

students = [
    {"id": 1, "name": "Aman"},
    {"id": 2, "name": "Rahul"}
]

def student_view(request):

    if request.method == "GET":
        return JsonResponse(students, safe=False)

    elif request.method == "POST":
        body = json.loads(request.body)
        students.append(body)
        return JsonResponse({"message": "Student added"})

Example for CBV:-

from django.views import View
from django.http import JsonResponse
import json

students = [
    {"id": 1, "name": "Aman"},
    {"id": 2, "name": "Rahul"}
]

class StudentView(View):

    def get(self, request):
        return JsonResponse(students, safe=False)

    def post(self, request):
        body = json.loads(request.body)
        students.append(body)
        return JsonResponse({"message": "Student added"})


Conclusion:-
“In FBV, handling multiple HTTP methods leads to large conditional blocks, making the code hard to maintain. CBVs solve this by mapping HTTP methods to class methods like get() and post(), resulting in cleaner and scalable code.”


****DRF Basics — APIView vs GenericAPIView vs ViewSet****
->What is DRF??
Django rest framework is used to build APIs. Instead of returning a HTTP response, we return a JSON file.

->Normal View VS API View
In Django, Normal View returns a HTML pages which are directly shown in the browser. But API view is used when we only want to send the data, not a full webpage. This data can be used by mobile apps or frontend frameworks like React to build the UI.
Django Normal View - Data + UI
Django API View - Only Data

->Generic View
GenericAPIView extends APIView and provides built-in functionality like queryset and serializer handling, making it easier to implement common CRUD operations with less code. It adds QuerySet and Serializer. Reduces Manual Work

->ViewSet(Most Powerful)
It handles all CRUD operations automatically

->Why we send Response instead of HttpResponse in DRF??
Because HttpResponse sends raw data, no automatic JSON handling. But Response automatically converts to JSON and it is also API friendly.
We can also create APIs through HttpResponse but we have to manually do everything like converting data to JSON.


****Serializers****
It converts python object to JSON and vice versa.
It does three important things:- (i)Validation (ii)Conversion and (iii)Save to database

What is the need of this??
It validates and structures the data.
Django models are like this:- Student(name="Amandeep", age=21)
But API need JSON structured data
Serializer does this for you.

But Response also doing the conversion to JSON only, then why there is need for Serializers?
Because Serializers also validates our data for each field. If in integer field we have typed a string, than it writes like "age must be of integer". And also it saves our data to the database
